# ТЗ: доработки веб-интерфейса Lichess Analyzer

**Версия:** 1.0  
**Дата:** 2026-11-01  
**Область:** веб-интерфейс, страницы игрока, поиск, прогресс, страница дебютов, избранное  
**Ограничение:** существующие таблицы партий не меняются; очистка и повторный импорт не требуются

---

## 1. Цель

Сделать интерфейс удобнее для просмотра истории партий и прогресса:

1. Принимать в поиске и имя игрока, и ссылку на профиль Lichess.
2. Показывать имя текущего игрока в шапке.
3. Показывать список игроков, уже загруженных в базу, на главной и на странице поиска.
4. Добавить на страницу дебютов фильтры по датам, сопернику и категории контроля времени + пагинацию.
5. На странице прогресса разделить графики по категориям контроля и добавить масштаб по времени (1/3/6 месяцев, всё время).
6. Добавить глобальное избранное с заметками, поиском и удалением.
7. Обеспечить корректное поведение на мобильных устройствах.

| Очистка базы | **Не требуется.** Существующие данные не трогаем |
| Контроль времени | Только категории: пуля, блиц, рапид, классика, переписка, другое |
| Прогресс по умолчанию | Последний использованный контроль |
| Список игроков | На главной и на странице поиска |
| `ui.show_known_players` | По умолчанию `true` |
| Пагинация на дебютах | Сразу |
| Имя игрока | В шапке сайта |
| Ввод профиля | Принимаем `@name`, `https://lichess.org/@/name`, URL с trailing slash и query |

| Удаление из избранного | Обязательно, идемпотентное |

## 3. Общие требования

- Все фильтры и страницы сохраняют состояние в URL (GET-параметры).
- Все SQL-запросы — параметризованные; имена таблиц экранируются.
- Никаких тяжёлых фоновых задач, Stockfish и анализа оценок в этой итерации.
- Мобильная версия — не «уменьшенный десктоп», а отдельные паттерны: карточки вместо таблиц, сворачиваемые фильтры, крупные touch-цели.
- Новые внешние зависимости не добавляются.
- Существующие таблицы `games_*` не изменяются. Единственный новый объект — таблица `favorite_games`.

## 4. Функция 1. Ввод имени или ссылки на профиль

### 4.1. Поддерживаемые форматы

| Ввод | Результат |
|---|---|
| `DenNedelin` | `DenNedelin` |
| `@DenNedelin` | `DenNedelin` |
| `https://lichess.org/@/DenNedelin` | `DenNedelin` |
| `http://lichess.org/@/DenNedelin/` | `DenNedelin` |
| `lichess.org/@/DenNedelin` | `DenNedelin` |
| `https://lichess.org/@/DenNedelin?tab=games` | `DenNedelin` |
| `https://example.com/@/DenNedelin` | ошибка «Это не ссылка на профиль Lichess» |
| `Den Nedelin`, `Den/Nedelin` | ошибка «Недопустимые символы в имени» |

### 4.2. Правила нормализации

1. Обрезать пробелы, убрать ведущий `@`.
2. Если строка содержит `://` или `lichess.org` — распарсить URL, проверить хост `lichess.org` / `www.lichess.org`, из пути извлечь `^/@/([A-Za-z0-9_-]+)/?$`.
3. Если это просто имя — проверить допустимые символы: латиница, цифры, `_`, `-`; длина 2–30.
4. Вернуть имя с сохранением регистра; для таблицы использовать существующее правило `games_<lower>`.
5. При ошибке — сообщение под полем, без запроса к Lichess и без создания таблицы.

### 4.3. Защита от «зависания»

- Валидация выполняется до `get_player_stats`, `download_games` и SQL-операций.
- `download_games` кодирует имя в URL (`quote(username, safe='')`).
- Ретраи только для `429`, `5xx` и таймаутов. На `400/404` — сразу ошибка.
- В текст ошибки не попадает HTML-ответ Lichess.
- Имя временного файла — только из нормализованного имени.
- `get_safe_table_name` заменяет все не-`[a-z0-9_]` на `_` и ограничивает длину 63 символами.
- Таблица игрока создаётся только после успешного скачивания непустого PGN.

### 4.4. UX

- Placeholder: `DenNedelin или https://lichess.org/@/DenNedelin`.
- Подсказка «Можно вставить ссылку на профиль».
- Ошибка — под полем, без перезагрузки.
- Кнопка на время запроса показывает спиннер и блокируется.
- 404: «Игрок не найден на Lichess. Проверьте имя или ссылку».
- 429: «Lichess временно ограничил запросы. Попробуйте через минуту».

## 6. Функция 3. Список игроков в базе

- Главная: блок «Мои игроки» под карточками.
- Поиск: блок «Мои игроки» под формой.
- Карточка: имя, количество игр, дата последней игры; вся карточка кликабельна.
- Сортировка: избранный игрок (`ui.featured_player`) первым, затем по дате последней игры.
- Лимит 8, при большем количестве — ссылка «Все игроки».
- Источник: `information_schema.tables` с `table_name LIKE 'games\_%'`, исключая legacy `games`.
- Для каждой таблицы: `COUNT(*)`, `MAX(game_date)`.
- Обновление истории: «Догрузить до N» (300 / 1000 / 3000) и «Обновить новые».
- Задачи импорта выполняются в фоне через таблицу `import_tasks`; статус
  опрашивается со страницы игрока.
- Кэш в памяти процесса на 10 секунд.
- Если `ui.show_known_players: false` — блок не рендерится и данные не запрашиваются.
- Известное ограничение: отображаемое имя — суффикс таблицы в нижнем регистре. Таблица `players` с исходным регистром — вне этой итерации.

### 6.1. Стримеры

- Курируемый список — `config/streamers.yaml` (`default_limit: 300`).
- Поля: `username`, `name`, `title`, `limit`, `enabled`.
- На странице поиска — отдельная секция «📺 Стримеры» со своей нумерацией.
- На странице игрока рядом с «Последними играми» — кнопка
  «Игры с <featured_player>» со счётчиком; ведёт на `openings?opponent=...`.
- Рядом с ником показывается русское имя и титул.
- «Загружен» = есть таблица `games_<username>`; иначе «не загружен».
- Стримеры не попадают в секцию «Мои игроки».
- Импорт — CLI `scripts/import_streamers.py` (300 игр по умолчанию).

## 7. Функция 4. Фильтры и пагинация на странице дебютов

### 7.1. Фильтры

| Фильтр | Параметр | Поведение |
|---|---|---|
| Дебют | `opening` | Подстрока `ILIKE %...%` |
| Результат | `result` (multi) | `Win` / `Loss` / `Draw`, OR внутри группы |
| Цвет | `color` | `white` / `black` / пусто |
| Дата с | `date_from` | ISO `YYYY-MM-DD`, включительно |
| Дата по | `date_to` | ISO, включительно через `< date_to + 1 day` |
| Соперник | `opponent` | Подстрока `ILIKE`, автодополнение |
| Категория контроля | `speed` | `bullet` / `blitz` / `rapid` / `classical` / `correspondence` / `other` |

Все условия объединяются через AND.

### 7.2. Категория контроля — без колонки

Общий SQL-фрагмент и эквивалентная Python-функция для тестов:

```sql
CASE
  WHEN time_control IS NULL OR time_control = '' THEN 'other'
  WHEN time_control = '-' OR time_control ILIKE '%day%' THEN 'correspondence'
  WHEN time_control ~ '^[0-9]+\+[0-9]+$' THEN
    CASE
      WHEN split_part(time_control,'+',1)::int + 40*split_part(time_control,'+',2)::int < 180  THEN 'bullet'
      WHEN split_part(time_control,'+',1)::int + 40*split_part(time_control,'+',2)::int < 480  THEN 'blitz'
      WHEN split_part(time_control,'+',1)::int + 40*split_part(time_control,'+',2)::int < 1500 THEN 'rapid'
      ELSE 'classical'
    END
  ELSE 'other'
END
```

Текущие данные: `300+3` → blitz (484), `900+10` → rapid (486), `-` и `* day per move` → correspondence (12).

### 7.3. Автодополнение соперника

- `GET /player/<username>/opponents?q=...&limit=10`.
- Ответ: `{ "items": [{"name": "...", "games": 12}, ...] }`.
- Пустой `q` — топ-10 соперников по количеству игр.
- Debounce 250 мс, минимум 2 символа.
- Кастомный выпадающий список, клавиатурная навигация, touch-строки 44 px.

### 7.4. Пагинация

- `page` (1-based), `per_page` (25 / 50 / 100), по умолчанию 50.
- Отдельный `COUNT(*)` с теми же фильтрами.
- `page` больше числа страниц — показывать последнюю.
- Смена фильтра сбрасывает `page=1`.
- Все ссылки пагинации сохраняют фильтры.
- Номер строки сквозной: `(page - 1) * per_page + loop.index`.

### 7.5. UX

- «Найдено: 124 · показано 50 (стр. 1 из 3)».
- «Сбросить фильтры» — только при активном фильтре.
- Активные фильтры — чипы с `×`.
- Пустой результат — сообщение и сброс.
- Форма GET, работает без JS; JS — автодополнение и пресеты дат.
- Пресеты: 1 день, 7 дней, 30 дней, 3 месяца, год, всё время.

### 7.6. Мобильные

- Фильтры свёрнуты в «Фильтры (N)»; на десктопе развёрнуты.
- Поля на всю ширину, даты — нативные, `font-size: 16px`.
- «Применить» — на всю ширину, 44 px.
- Результаты — `.mobile-cards`.
- Пагинация — крупные кнопки, текущая/всего.
- Переход по странице — с якорем `#results`.

## 8. Функция 5. Прогресс: категории контроля и период

### 8.1. Табы категорий

- Над графиком: «Блиц (484)», «Рапид (486)», «Переписка (12)».
- Только категории, где есть игры.
- Выбранная категория — в URL `?tc=blitz`.
- Приоритет: URL → cookie `la_tc` → категория последней игры.
- При выборе таба cookie `la_tc` (Max-Age 1 год, Path=/, SameSite=Lax).
- Недоступная категория в cookie — fallback на последнюю игру.

### 8.2. Период

- `period`: `1d` / `1w` / `1m` / `3m` / `6m` / `all`, по умолчанию `3m`.
- Окна: 1 день (сегодня), 7 / 30 / 90 / 180 дней.
- Фильтр по дате применяется вместе с категорией.

### 8.3. График

- X-ось — даты (`DD.MM`).
- Y-ось — рейтинг, без `beginAtZero`.
- Две линии: мой рейтинг и рейтинг соперника (пунктир).
- Переключатель «Линия / Точки»; на мобильных по умолчанию линия.
- Чекбокс «Рейтинг соперника»; на мобильных по умолчанию выключен.
- Клик по точке открывает страницу партии.
- Точки окрашены по результату.
- Отдельный столбчатый график «Игр по дням» под рейтинговым; считается
  по тем же фильтрам контроля и периода, нулевые дни показываются.
- Переключатель «выбранный контроль / все контроли» и сумма за режим.
- Tooltip: дата, результат, дебют, цвет, контроль.
- Высота 300 px десктоп / 240 px мобильный.
- Подписи по X — 6–8 штук.

### 8.4. Таблица и статистика

- Таблица — только выбранная категория и период.
- В шапке карточки — «Игр: N» и «Побед: N (X%)» за выбранный период.
- Последние 50 строк; ссылка «Все партии за период» на страницу дебютов с фильтрами.
- Статистика периода: победы/поражения/ничьи, изменение рейтинга.
- `by_time_control` остаётся общей, выбранная строка подсвечивается.
- Пустой результат — empty state с кнопкой «Показать всё время».

### 8.5. Мобильные

- Табы — горизонтальный скролл.
- Период — 4 сегмента в 2 ряда или `<select>`.
- График не выходит за ширину.
- Таблица — карточки или горизонтальный скролл.
- Статистика — в одну колонку.

## 9. Функция 6. Избранное и заметки

### 9.1. Хранение

Единая таблица `game_annotations` со снимком метаданных:

```sql
CREATE TABLE IF NOT EXISTS game_annotations (
    player_username  VARCHAR(100) NOT NULL,
    game_id          VARCHAR(20)  NOT NULL,
    game_date        TIMESTAMP,
    opponent_name    VARCHAR(100),
    opponent_rating  INTEGER,
    player_color     VARCHAR(10),
    result           VARCHAR(10),
    opening_name     VARCHAR(200),
    time_control     VARCHAR(20),
    move_count       INTEGER,
    my_rating        INTEGER,
    game_url         VARCHAR(200),
    note             TEXT,
    is_favorite      BOOLEAN NOT NULL DEFAULT FALSE,
    created_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    updated_at       TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    PRIMARY KEY (player_username, game_id)
);

CREATE INDEX IF NOT EXISTS idx_ann_created
    ON game_annotations (created_at DESC);
CREATE INDEX IF NOT EXISTS idx_ann_player
    ON game_annotations (player_username);
CREATE INDEX IF NOT EXISTS idx_ann_game_date
    ON game_annotations (game_date DESC);
CREATE INDEX IF NOT EXISTS idx_ann_favorite
    ON game_annotations (is_favorite) WHERE is_favorite;
```

- `player_username` — в нижнем регистре.
- Снимок заполняется при добавлении из строки партии или страницы просмотра.
- При удалении игрока чистим его избранное и заметки (game_annotations).

### 9.2. Добавление и удаление

- `POST /favorites` — `{player_username, game_id}`, идемпотентно; ответ `{favorited: true, count: N}`.
- `DELETE /favorites/<player>/<game_id>` — 204, идемпотентно.
- `PATCH /favorites/<player>/<game_id>` — `{note}` (совместимость).
- `PATCH /annotations/<player>/<game_id>` — `{note}`; создаёт строку для любой партии.
- `GET /annotations/<player>/<game_id>` — `{note, is_favorite, updated_at}`.
- CSRF через `X-CSRFToken`.
- Звёздочка `☆ / ★` в таблице, мобильной карточке и на странице партии.
- На мобильном кнопка всегда видима, 44×44, `aria-pressed`.

### 9.3. Страница `/favorites`

- Глобальная, по всем игрокам.
- Одно поле поиска `q`: `player_username`, `opponent_name`, `opening_name`, `note`.
- Сортировка: «недавно добавленные» (по умолчанию), «по дате партии».
- Пагинация 25 / 50 / 100.
- Карточка: игрок, дата, цвет, результат, соперник, дебют, контроль, заметка, кнопки «Смотреть», «Убрать», «✎ Заметка».
- Заметка: plain text, до 2000 символов, `white-space: pre-wrap`.
- Убрать из избранного не удаляет заметку; строка удаляется только если
  нет ни заметки, ни избранного.
- Горячие клавиши просмотрщика не перехватывают пробел/стрелки
  в полях ввода и textarea.
- Пустое состояние с подсказкой.
- Счётчик `⭐ Избранное (N)` в шапке всегда; обновляется из ответов API.

### 9.4. Страница `/notes`

- Отдельный пункт `📝 Заметки` в шапке со счётчиком.
- Поиск `q`: текст заметки, игрок, соперник, дебют.
- Сортировка: недавно изменённые / дата партии / соперник.
- Пагинация 25 / 50 / 100.
- Иконка `📝` во всех списках: последние игры, фильтр, длина партий,
  прогресс, избранное, просмотр партии.
- Заполненная иконка — заметка есть; модалка с `Ctrl+Enter`.

### 9.5. Мобильные

- «Избранное» — пункт верхней навигации.
- Поиск на всю ширину, фильтры не нужны (только `q` и сортировка).
- Карточки в одну колонку, заметка — превью, редактор в модалке/bottom sheet.
- Удаление — кнопкой, без свайпов.

## 13. Миграции и развёртывание

- SQL создания `favorite_games` — в одном общем модуле.
- `scripts/setup_db.py --action create` создаёт `favorite_games` после основной таблицы.
- `scripts/migrations/001_create_favorite_games.py` — идемпотентная миграция с `--status` и `--apply`.
- Опционально `create_app()` вызывает `ensure_favorites_table()` для автосоздания.
- `CREATE TABLE IF NOT EXISTS` + advisory lock защищают от гонки воркеров.
- `--drop-table` и `--recreate` не удаляют избранное без отдельного флага.
- Существующие таблицы игроков не изменяются.

Перед первым запуском избранного на сервере:

```bash
python scripts/setup_db.py --action create
# или
python scripts/migrations/001_create_favorite_games.py --apply
```

## 14. Критерии приёмки

1. Вставка URL профиля в поиск открывает игрока; ошибок и зависаний нет.
2. Невалидный URL даёт ошибку без запроса к Lichess.
3. Имя игрока видно в шапке на всех страницах игрока, на десктопе и мобильном.
4. Список игроков виден на главной и в поиске; при `show_known_players: false` скрыт и не запрашивается.
5. На дебютах работают фильтры и пагинация, счётчик «найдено/показано» корректен.
6. На мобильном фильтры свёрнуты, результаты — карточками.
7. На прогрессe есть табы контролей и периоды; выбор сохраняется.
8. Таблица и статистика прогресса соответствуют выбранному контролю и периоду.
9. Избранное добавляется, удаляется, счётчик обновляется, заметка сохраняется.
10. Поиск по избранному находит по игроку, сопернику, дебюту и заметке.
11. Схема существующих таблиц не изменилась; данные не очищались.
12. Все страницы проверены на 1280, 768, 480, 390 px.
